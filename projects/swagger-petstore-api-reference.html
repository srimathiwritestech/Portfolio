DEVELOPER DOCUMENTATION · API REFERENCE

Swagger Petstore
API Reference.

A portfolio-created API reference sample showing how I structure developer documentation around endpoint intent, request parameters, response behavior, schemas, examples, and verification.

TYPEAPI reference
FORMATREST / JSON
SAMPLE APISwagger Petstore
01

Retrieve a pet by ID.

Use this endpoint to retrieve detailed information about a specific pet using its unique identifier.

GET · ENDPOINT/pet/{petId}
BASE URL

https://petstore.swagger.io/v2

EXAMPLE REQUEST

https://petstore.swagger.io/v2/pet/983680

02

Document what developers need before they call it.

This operation requires one path parameter. It does not require query parameters or a request body.

ParameterLocationTypeRequiredDescription
petIdPathIntegerYesUnique identifier of the pet to retrieve.
Request body

Not required for this GET operation.

03

Make response outcomes easy to scan.

StatusDescription
200Successful retrieval of pet details.
400Invalid ID supplied.
404Pet not found.
TESTED RESPONSE200 OK — pet details returned successfully.
04

Describe the response at field level.

FieldTypeDescription
idIntegerUnique identifier of the pet.
categoryObjectCategory assigned to the pet.
category.idIntegerUnique category identifier.
category.nameStringName of the category.
nameStringName of the pet.
photoUrlsArray of stringsList of photo URLs associated with the pet.
tagsArray of objectsTags associated with the pet.
tags.idIntegerUnique identifier of the tag.
tags.nameStringName of the tag.
statusStringCurrent status of the pet.

06

Give developers a runnable example.

A cURL example gives developers a quick way to make the request from a terminal and verify endpoint behavior.

curl --request GET \
  --url https://petstore.swagger.io/v2/pet/983680 \
  --header 'Accept: application/json'

07

The documentation decisions behind the page.

01 / INTENT

Start with the task

Lead with what the endpoint does instead of making developers decode the API structure first.

02 / SCAN

Structure for speed

Separate request, response, schema, and examples so developers can jump to what they need.

03 / PRECISION

Use concrete language

Describe parameters and response fields in terms of what developers need to do with them.

04 / VERIFY

Make it testable

Provide a runnable cURL example and a link to the public API response.

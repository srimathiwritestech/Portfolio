Developer documentation has to support different intents: learning, completing a task, configuring a component and looking up a detail.

02 / MY APPROACH

Make the user's path visible.

I separate conceptual, task-oriented and reference content so developers can move quickly without losing the context they need.

Learn → Install → Configure → Use → Troubleshoot → Reference

03 / DOCUMENTATION STRATEGY

Structure follows intent.

The documentation supports action while preserving enough conceptual context to make the product easier to understand.
